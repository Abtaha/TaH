# Confirmatory input contract

`analyze.py` now uses the CPU statistics implementation in
`script/tah/evaluation/compare_runs.py` when R1 inputs exist. It calls
`_run_group` and `_pair_analysis` directly so the input data stays confined to
this chapter; it does not resolve live datasets through the protocol runner.
The tool supplies Student-t paired intervals and TOST. Ordinary historical
analysis is standard-library only; this optional import also needs PyYAML,
already present in `.venv-tah`.

Run confirmatory generation with the committed protocol presets and runner,
following `report/PROTOCOL.md` and `guide/evaluation.md`. Do not substitute the
exploratory engine outputs for fresh frozen-engine runs. Retain canonical per-sample CSVs, effective configuration, complete status and
protocol provenance beneath `data/r1/`; keep full generations and telemetry in
the experiment directories and record their source paths. The existing
exploratory reference CSVs support reference-versus-reference noise. Verify the settings,
seeds and engine source hashes before setting `complete`.

Add `data/r1/inputs.json` with this structure (paths are relative to `data/`):

```json
{
  "complete": true,
  "frozen_engine_sha256": "<SHA256 of the frozen engine source inventory>",
  "reference": {"seed": 1234, "path": "r1/reference-seed1234"},
  "engine": [
    {"seed": 42, "path": "r1/engine-seed42", "frozen_engine_sha256": "<same hash>"},
    {"seed": 1234, "path": "r1/engine-seed1234", "frozen_engine_sha256": "<same hash>"},
    {"seed": 2024, "path": "r1/engine-seed2024", "frozen_engine_sha256": "<same hash>"}
  ],
  "deviations": []
}
```

Register **every** added file in `data/MANIFEST.json` using the existing entry
schema (source/stored SHA256, path, size, encoding, purpose and schema keys).
The analyzer refuses undeclared files or hash mismatches, checks expected
problem/repeat coverage and complete run statuses, and uses the frozen source
hash declarations. The declarations do not independently prove which code was
executed; retain a frozen engine source inventory alongside the runner's command/config records and review them.

Missing index, `complete: false`, missing run files or incomplete statuses yield
a pending section without a false verdict. Corrupt hashes, duplicate pairs,
wrong seeds, inconsistent engine hashes or invalid coverage fail loudly.
On completion, `tables/r1.tex` and `tables/r1-analysis.json` include pooled and
per-dataset engine/reference comparisons, reference self-noise, pass ratios,
TOST and deviations. The analyzer never reruns generation to obtain a pass.
